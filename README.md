# meta-helium

Torizon OS support for the PCB Arts Helium (Jetson Orin NX 16GB, `MACHINE = "helium-orin-nx"`).

- Target: **Torizon OS 8 (wrynose)**, meta-tegra `wrynose` = **L4T R39.2.1 / JetPack 7.2.1**, kernel `linux-noble-nvidia-tegra` 6.8.
- Base: meta-tegra `orin-nx.inc` (P3767-0000 in P3768-style carrier, NVMe rootfs).
- ODMDATA `gbe-uphy-config-9` (PCIe C9 x1 for the LAN7430).
- Pinmux/GPIO/pad-voltage from the PCB Arts JetPack 36.5.0 package; MB2 misc BCT patched to skip the (absent) carrier EEPROM
  (`orin_generic_v36.5.0_helium_2026-05-19`), generated by them from `helium_dp.xlsm`.
- Kernel DTB = stock `nv-super` DTB + `tegra234-p3768-0000+p3767-0000-helium-overlay.dts`, merged at build time.
- Kernel config fragment for LAN743X, MCP7940 RTC, ICM-42670 IMU, ATSHA204A, WWAN modems.

Not yet covered: MAX96724 GMSL2 cameras, fan control (`helium_fan_gpio_config`), LAN743X EEPROM MAC setup.

## Build

Workspace: repo manifest `https://github.com/torizon/manifest`,
branch `wrynose-8.x.y`, file `torizon/nvidia/release.xml`. Container `torizon/crops:wrynose-8.x.y`.

    cd <workspace>
    ./bb.sh torizon-docker            # build dir build-helium
    tail -f build-helium.log          # ends with BUILD_EXIT=<code>

The config was generated with `MACHINE=jetson-orin-nano-devkit-nvme` (Torizon's `lib/machines.conf`
doesn't know `helium-orin-nx`), then `MACHINE` switched in `conf/auto.conf` and meta-helium added to
`EXTRALAYERS`. `bb.sh` only sources `oe-init-build-env`, so the config is not regenerated.

Output: `build-helium/deploy/images/helium-orin-nx/torizon-docker-helium-orin-nx.tegraflash.tar.zst`

## Flash (x86 Linux host)

1. Extract the tegraflash tarball (as root/sudo, on an ext4 filesystem).
2. Recovery mode: power off Helium, connect USB-C to the host, power on. `lsusb` shows `0955:7323` (Orin NX 16GB).
3. NVMe rootfs: `sudo ./initrd-flash`.
4. To go back to the PCB Arts image, use their package
   (`orin_generic_v36.5.0_helium_2026-05-19.extractor.sh`) and
   `l4t_initrd_flash.sh ... jetson-orin-nano-devkit-super-nvme internal`.
